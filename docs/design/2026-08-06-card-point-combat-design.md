# 卡牌点数持续消耗战斗设计

**日期：** 2026-08-06  
**状态：** 已确认设计，待用户审阅  
**范围：** 牌链遭遇战斗逻辑、卡牌点数损耗、牌根特殊处理、残响结果效果

## 1. 设计目标

将现有逐张卡牌触发伤害、防御、治疗以及怪物行动的战斗，简化为直观的点数比较：

> 从牌链末尾开始，卡牌当前点数与残响当前生命比较；卡牌点数归零才离场，残响生命归零即被击败。

棋盘、牌链连接、事件接触、牌桌持续存在和探索流程保持不变，主要修改战斗结算逻辑。

核心循环：

```text
购买更高点数卡牌 -> 组成牌链 -> 消耗残响生命 -> 保留有点数的卡牌 -> 获得金币升级 -> 挑战 Boss
```

## 2. 数据模型

### 卡牌

每张卡牌拥有：

- `max_points`：最大点数；
- `current_points`：当前点数。

`current_points` 是探索中的运行时状态。卡牌参与战斗后，当前点数下降并在战斗结束后保留。

### 牌根

牌根也拥有最大点数和当前点数，但点数归零时执行特殊处理：

```text
牌根 current_points = 0
-> 重置为 max_points
-> 从牌桌返回手牌区
```

牌根不会永久损失。

### 残响

残响保留：

- 最大生命 `max_hp`；
- 当前生命 `current_hp`；
- 奖励掉落；
- 结果惩罚；
- 可选的特殊战败效果。

## 3. 末尾优先结算

牌链：

```text
牌根 -> 卡牌 A -> 卡牌 B -> 卡牌 C
```

结算顺序：

```text
卡牌 C -> 卡牌 B -> 卡牌 A -> 牌根
```

每张卡牌最多与当前残响生命比较一次。

### 卡牌点数小于残响生命

```text
残响 current_hp -= 卡牌 current_points
卡牌 current_points = 0
普通卡牌从牌桌移除
继续结算前一张卡牌
```

### 卡牌点数等于残响生命

```text
残响被击败
卡牌 current_points = 0
普通卡牌移除
战斗结束
```

### 卡牌点数大于残响生命

```text
卡牌 current_points -= 残响 current_hp
残响 current_hp = 0
残响被击败
卡牌保留在牌桌
战斗结束
```

溢出点数不转化为其它资源。

## 4. 牌桌状态

- 普通卡牌只有 `current_points <= 0` 时才从牌桌移除；
- 未参与结算的卡牌不返回手牌、不扣点数，继续留在牌桌；
- 仍有点数的已使用卡牌继续留在牌桌；
- 牌根只有在实际结算后归零，才重置点数并返回手牌；
- 战斗中途击杀残响时，前方尚未结算的卡牌保持原状态。

示例：

```text
牌根 2 -> A 4 -> B 7 -> C 3
残响 4 生命

C：3，残响 4 -> 1，C 归零并移除
B：7，击杀残响，B 保留 6

战斗后：牌根 2、A 4、B 6 留在牌桌，C 被移除
```

## 5. 战斗结果

继续使用现有枚举：

```gdscript
enum Outcome { VICTORY, RETREAT, DEFEAT }
```

### `VICTORY`

残响生命归零，完成事件并发放已有金币和卡牌掉落。牌桌只反映本次实际点数损耗。

### `RETREAT`

当前牌链已经从末尾结算到牌根，但残响仍存活。残响保留已损失生命；未使用卡牌留在牌桌；执行现有 `CombatResult.penalties` 惩罚框架。

`RETREAT` 不再表示怪物行动，只表示当前牌链未能完成击杀。

### `DEFEAT`

保留给玩家失败流程。基础点数比较不主动插入普通怪物行动；特殊残响可以配置额外战败效果。

## 6. 惩罚和特殊残响效果

卡牌因点数归零而移除，与惩罚主动移除卡牌是两种不同机制：

```text
点数归零：基础战斗规则
惩罚移除：结果处理阶段的附加规则
```

现有 `CombatResult.penalties` 保留，可以继续承载：

- 移除牌链末尾卡牌；
- 残响强化；
- 扣除信仰值；
- 移动残响事件；
- 生成新的残响。

特殊残响建议按结果配置效果入口：

```text
on_retreat_effects
on_defeat_effects
on_victory_effects
```

例如：

- `RETREAT`：下次挑战自身恢复 2 点生命；
- `RETREAT`：获得 1 层强化；
- `DEFEAT`：玩家战败时扣除信仰值；
- `DEFEAT`：玩家战败时生成新的残响；
- `VICTORY`：Boss 击败后推进地图或回收神性。

`CombatService` 只负责点数比较和结果，不直接处理金币、信仰值、地图事件或牌桌节点。

## 7. 卡牌配合边界

保留牌链配合，但配合只修改当前比较点数或卡牌最大点数，不重新引入怪物行动队列、异常状态或复杂效果。

首版可支持：

- 上一张卡牌仍有点数：当前比较点数 `+1`；
- 上一张卡牌刚好归零：当前比较点数 `+2`；
- 连续两张同类型卡牌：第二张比较点数 `+1`。

临时比较点数与卡牌持久点数必须区分：

```text
比较点数：本次比较使用的临时值
当前点数：卡牌实际保留的运行时点数
```

首版默认不让临时加成永久增加卡牌当前点数。


### 7.1 配合边界与计算公式

“卡牌配合”只改变当前卡牌本次战斗的比较点数，不负责修改牌桌结构、卡牌回手、卡牌移除、地图事件、金币、信仰值或残响结果。

当前卡牌结算时使用：

```text
effective_points = card.current_points + synergy_bonus
```

其中：

- `card.current_points` 是卡牌持久保留的当前点数；
- `synergy_bonus` 是本次比较临时产生的配合加成；
- `effective_points` 是本次与残响生命比较的最终点数。

比较完成后，卡牌剩余点数按本次最终比较点数计算：

```text
if effective_points < monster.current_hp:
    monster.current_hp -= effective_points
    card.current_points = 0

if effective_points == monster.current_hp:
    monster.current_hp = 0
    card.current_points = 0

if effective_points > monster.current_hp:
    card.current_points = effective_points - monster.current_hp
    monster.current_hp = 0
```

因此，临时配合加成可能转化为击杀后的剩余点数，但不会单独修改卡牌的最大点数。

由于战斗从牌链末尾向牌根结算，规则中不使用含义模糊的“上一张卡牌”。应使用“后置卡牌”表示原牌链中位于当前卡牌后方、更加接近牌链末尾且已经先结算的卡牌。

第一版允许的配合只读取：

- 当前卡牌类型和标签；
- 后置卡牌类型和标签；
- 后置卡牌结算后是否仍有点数；
- 后置卡牌是否刚好归零；
- 当前卡牌在牌链中的位置和牌链长度。

第一版配合示例：

```text
后置卡牌结算后仍保留点数 -> 当前卡牌 synergy_bonus +1
后置卡牌刚好归零 -> 当前卡牌 synergy_bonus +1
连续两张同类型卡牌 -> 后一张卡牌 synergy_bonus +1
牌链达到指定长度 -> 当前卡牌 synergy_bonus +1
```

配合不能直接触发另一张卡牌的完整效果，不能直接移除未使用卡牌，不能重置普通卡牌，不能修改玩家资源或地图，也不能触发怪物行动。
## 8. 第一关平衡方向

| 内容 | 建议数值 |
|---|---:|
| 牌根最大点数 | 2 |
| 基础卡牌最大点数 | 1～3 |
| 配合卡最大点数 | 3～5 |
| 啮髓鼠群生命 | 3～4 |
| 腐肋巨狼生命 | 8～10 |
| 白角守墓鹿生命 | 18～22 |

目标：

- 啮髓鼠群通常消耗 1～2 张低点数卡牌；
- 腐肋巨狼需要 3～4 张有效卡牌或一张高点数卡牌配合；
- Boss 要求玩家完成商店购买和牌链构筑，而不是依赖初始牌组；
- 高点数卡牌击杀低生命残响后仍可保留部分点数。

## 9. 架构改动边界

主要修改：

- `CombatService2`：改为末尾向牌根的点数结算；
- `CombatContext`：增加反向牌链游标和卡牌点数变化记录；
- `CombatResult`：保留结果、残响状态、已处理卡牌和惩罚字段，废弃普通怪物行动结果字段；
- `CardData` / `CardInstance`：补充最大点数和当前运行时点数；
- 牌桌/卡牌管理器：处理普通卡牌归零移除、牌根归零重置回手；
- 残响配置：增加按 `RETREAT`、`DEFEAT`、`VICTORY` 配置效果的入口。

不修改：

- 棋盘尺寸和卡牌连接规则；
- 事件接触触发方式；
- 商店、宝藏、奖励掉落总体流程；
- Boss 追击服务的事件移动逻辑；
- 现有惩罚框架的结果传递方式。
