# MonoCard 自适应窗口与等比游戏画布设计

**日期：** 2026-08-02
**状态：** 已确认，待实现计划
**目标：** 支持不同窗口尺寸和屏幕比例，同时保持棋盘、牌链、事件圈与卡牌的逻辑关系和视觉比例稳定。

## 1. 背景与问题

当前项目以 `1600×900` 为设计尺寸。棋盘格、卡牌实体及手牌位置使用固定像素常量；窗口变化时，`GameManager` 只重新居中棋盘与手牌，不会统一缩放玩法内容。因此在更大、超宽或非 16:9 窗口中，玩法区会显得过小或出现未利用区域。

卡牌的逻辑占位（当前为 `1×2` 格）不能直接由卡面长宽比决定。改变卡牌视觉比例不应破坏棋盘占格、牌链连接、事件触发或碰撞判定。

## 2. 已确认的设计原则

1. **逻辑占位与视觉比例分离。** 卡牌继续使用既有 `1×2` 棋盘占格；卡面可以在槽位中使用独立的经典卡牌视觉比例。
2. **棋盘玩法内容整体等比缩放。** 不单独缩放格子、卡牌或事件圈；它们必须处在同一个变换根节点下。
3. **窗口额外空间由背景承担。** 不为填满超宽或超高窗口而拉伸棋盘、卡牌或圆形事件圈。
4. **玩法区与屏幕 UI 分层。** 商店、宝藏、战斗结算等模态 UI 使用 `Control` 的响应式布局，独立于棋盘缩放。
5. **保持可读性。** 窗口过小时限制最小可玩尺寸；窗口过大时限制玩法区最大缩放，避免棋盘过散。

## 3. 目标结构

```text
Main
├─ BackgroundLayer
│  └─ 全屏森林、雾气、远景与装饰
├─ GameCanvas
│  ├─ Board
│  ├─ HandManager
│  ├─ CardManager
│  └─ DragLayer
└─ UILayer (CanvasLayer)
   ├─ 常驻 HUD
   ├─ ShopEventView
   ├─ TreasureEventView
   └─ CombatEventView
```

### 3.1 BackgroundLayer

- 采用可平铺、可裁切或分层视差的背景资源填满整个窗口。
- 超宽屏两侧和 16:10/更高屏幕的额外纵向区域显示环境内容，而不是黑边。
- 背景不参与棋盘、卡牌和事件的输入或碰撞。

### 3.2 GameCanvas

- 作为棋盘玩法对象的共同父节点。
- 按设计尺寸 `1600×900` 中预留的玩法区域进行统一缩放和居中。
- 缩放比例为可用尺寸的宽高缩放比例中的较小者：

```text
scale = min(available_width / design_width,
            available_height / design_height)
```

- 缩放范围设为可配置的最小值与最大值。首版建议：`0.8 ~ 1.35`。
- 超过最大值的屏幕空间保留给背景，而不继续放大棋盘。
- 缩小到最小值后若仍无法保证可读性，依赖窗口最小尺寸限制，而非继续压缩玩法区。

### 3.3 UILayer

- 保持在 `CanvasLayer`，不成为 `GameCanvas` 的子节点。
- 模态根节点采用全屏锚点；面板通过最大宽度、边距与容器在不同窗口下适配。
- 宽屏时面板保持易读宽度并居中；窄屏时收缩间距，日志/商品区允许滚动。

## 4. 不同窗口比例的预期表现

| 窗口类型 | GameCanvas | 额外区域 |
| --- | --- | --- |
| 16:9 | 等比放大至主要玩法区 | 少量安全边距与背景 |
| 16:10 / 较高屏幕 | 由较短边限制缩放，玩法区居中 | 上下背景空间 |
| 21:9 / 超宽屏 | 主要按高度确定缩放，受最大缩放限制 | 左右森林、雾气和装饰 |
| 小于推荐尺寸 | 缩放到最小可读尺度 | 窗口尺寸限制阻止继续缩小 |
| 极端比例 | 不拉伸内容 | 背景填补扩展区域 |

## 5. 项目设置方向

- 保留 `window/stretch/mode="canvas_items"`，避免对 CanvasItem 进行非等比拉伸。
- 明确采用可扩展的窗口比例策略，使根视口可反映实际可用尺寸。
- 建议设置推荐最小窗口尺寸 `1280×720`；绝对下限可在实现时根据文字和交互测试调整。

## 6. 实现边界

本次实现将覆盖：

- 新增统一的 `GameCanvas` 结构或等价的玩法根节点；
- 统一计算、更新其等比缩放和居中位置；
- 迁移棋盘、手牌、卡牌管理与拖拽层至同一坐标体系；
- 将背景扩展区域作为纯视觉层；
- 为窗口尺寸变化、极端长宽比、最小/最大缩放增加测试。

本次不覆盖：

- 卡牌插画、边框与最终视觉比例的美术重制；
- 多分辨率字体资源与完整无障碍字体缩放策略；
- 移动端竖屏布局；
- 相机拖拽、缩放或自由棋盘平移。

## 7. 验收标准

1. 从推荐窗口尺寸扩大到 16:9、16:10、21:9 时，棋盘、卡牌、事件圈与拖拽命中区域保持一致的相对位置和比例。
2. 游戏内容不发生横向或纵向形变；圆形事件圈保持圆形。
3. 在超过最大缩放的窗口中，棋盘不继续变大，额外空间由背景呈现。
4. 在允许的最小窗口中，手牌、卡牌文本与主要交互仍可读、可点。
5. 商店、宝藏与战斗模态始终覆盖实际窗口区域，并不随 GameCanvas 一起缩放。
6. 自动化测试覆盖缩放比例计算、居中位置、最小/最大缩放钳制与窗口变化后的布局更新。
