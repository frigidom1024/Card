# 引导牌玩法设计

- 日期：2026-08-05
- 状态：已确认，待实施

## 1. 背景

游戏将改造成贪吃蛇式的牌链玩法。新增一种“引导牌”：它遵循普通卡牌的放置合法性，但成功放置后不会加入牌桌，而是推动现有牌链整体向前移动一格，然后回到手牌区。

当前项目的牌桌由 `Board.cards` 按连接顺序维护，拖拽交互由 `DragLayer` 负责，手牌由 `HandArea` 管理，`GameManager` 负责场景节点之间的连接和运行时协调。

## 2. 范围

本次改动只负责：

- 在 `CardData.CardType` 中新增 `GUIDE` 类型；
- 让运行时能识别引导牌；
- 让引导牌遵循普通牌放置检查；
- 成功放置后推动现有牌链前移；
- 让引导牌通过信号返回手牌。

本次不负责：

- 将引导牌加入任何起始牌组；
- 修改抽牌、商店、奖励或牌组配置；
- 新增引导牌资源实例；
- 改变普通牌、ROOT 牌的既有规则；
- 为引导牌添加独立战斗效果。

## 3. 核心规则

### 3.1 卡牌类型

在 `CardData` 中扩展：

```gdscript
enum CardType {
    ROOT,
    NORMAL,
    GUIDE,
}
```

引导牌是否出现在牌组中不由这个类型负责，本次不改动牌组数据。

### 3.2 放置校验

引导牌从手牌拖出后沿用普通牌的放置流程：

- 使用现有棋盘边界检查；
- 使用现有牌链相邻检查；
- 使用现有卡牌占用冲突检查；
- 使用现有旋转和预览逻辑；
- 牌桌为空时，因引导牌不是 ROOT，不能单独建立牌链。

非法放置时不触发引导牌效果，由现有 `DragLayer` 逻辑将卡牌退回手牌。

### 3.3 牌链前移

假设当前牌链为：

```text
卡牌1位置 → 卡牌2位置 → 卡牌3位置 → 引导牌位置
```

引导牌成功放置后，最终状态为：

```text
空位      → 卡牌1位置 → 卡牌2位置 → 卡牌3位置
```

卡牌映射为：

```text
卡牌3 = 引导牌原来的位置和朝向
卡牌2 = 卡牌3原来的位置和朝向
卡牌1 = 卡牌2原来的位置和朝向
```

因此：

- `Board.cards` 的顺序不变；
- 每张卡牌移动到前方卡牌的旧位置；
- 每张卡牌同时继承目标位置对应的旋转方向；
- 原本第一张牌的位置释放为空位；
- 引导牌自身不进入 `Board.cards`；
- 棋盘占用表根据移动后的最终状态一次性重建，避免移动过程中的临时碰撞。

引导牌放置位置必须是合法的空位置，因此它可以作为牌链新的前进目标。

## 4. 职责划分与信号

### 4.1 Board

`Board` 保留统一的公开放牌入口：

```gdscript
func add_card(card: CardEntity) -> bool
```

不新增 `add_guide_card()` 公共接口。

`Board.add_card()` 在完成通用校验后，根据卡牌类型执行不同的内部行为：

- 普通牌和 ROOT 牌：沿用现有加入牌桌逻辑；
- GUIDE 牌：执行牌链前移，不加入 `Board.cards`。

新增信号：

```gdscript
signal card_return_requested(card: CardEntity)
```

引导牌前移成功且棋盘状态更新完成后，`Board` 发出该信号。

`Board` 不直接依赖 `HandArea`，也不负责将卡牌重新加入手牌。

### 4.2 GameManager

`GameManager` 作为场景协调者连接 `Board.card_return_requested`，并调用 `HandArea.add_card(card)`：

```text
Board.card_return_requested
    → GameManager 回调
    → HandArea.add_card(card)
```

这样实际的跨区域转发由 `GameManager` 完成，而卡牌的手牌状态和布局仍由 `HandArea` 管理。

### 4.3 DragLayer

`DragLayer` 不增加引导牌类型判断。拖拽结束时继续使用：

```gdscript
if board.add_card(card):
    return
```

引导牌成功放置后，`Board` 同步发出信号，`GameManager` 将其回收到手牌；`DragLayer` 不重复添加。

## 5. 表现与交互

逻辑状态需要在一次操作中完成更新。视觉表现可以使用短时长 Tween，让牌链中的所有卡牌同时移动并同步旋转到新位置。

移动期间应避免开始新的拖拽，防止棋盘占用状态与视觉状态不同步。测试不依赖 Tween 时长，直接验证最终状态。

引导牌回到手牌时：

- 重置为手牌状态；
- 旋转重置为 0；
- 使用现有手牌排列和动画；
- 手牌计数正常更新。

由于引导牌来自手牌，正常情况下回手不会触发容量问题；如果回收失败，应保留现有交互恢复机制并记录错误，不能静默丢牌。

## 6. 事件处理

引导牌仍然遵循普通卡牌的放置检查。若引导牌目标位置对应未解决事件，事件触发判断应基于牌链前移后的最终棋盘占用状态：前移后的牌链尾部卡牌占据该位置，引导牌本身不占据牌桌。

## 7. 测试计划

新增或扩展测试覆盖：

1. `CardType.GUIDE` 可以被正确识别；
2. 合法引导牌放置后只发出一次 `card_return_requested`；
3. 引导牌不出现在 `Board.cards`；
4. 引导牌回到 `HandArea.cards`；
5. 多张牌前移后牌链顺序不变；
6. 每张牌获得前方卡牌的旧位置；
7. 每张牌继承前方卡牌旧位置的朝向；
8. 原第一张牌的位置被释放；
9. `_grid_owner` 与最终卡牌位置一致；
10. 单张牌也能正确前移；
11. 空牌桌不能放置引导牌；
12. 非法放置时牌链不变且不触发回手信号；
13. 普通牌和 ROOT 牌的现有放置测试继续通过；
14. 既有牌组数据不发生变化。

## 8. 验收标准

- 项目可以加载包含 `GUIDE` 类型的 `CardData`；
- 引导牌能从手牌按普通牌规则拖到牌链前方；
- 成功后现有牌链整体前移，位置和朝向均保持连接；
- 引导牌不留在牌桌，且通过 `Board` 信号回到手牌；
- 普通牌、ROOT 牌和现有事件流程无回归；
- 自动化测试覆盖核心规则并全部通过。
