# 《PILGRIM'S CHAIN》卡牌详情 UI 设计

**日期：** 2026-08-03  
**状态：** 已确认，待实施计划  
**范围：** 卡牌悬浮信息与卡牌放大查看界面的视觉、内容层级、共享组件和验证边界。

## 1. 目标

将目前基础的纯文字悬浮信息和早期高饱和放大面板，统一为与主页一致的“Field Ledger（旅途札记）”视觉系统：墨蓝近黑、骨白文字、旧金细描边、低饱和属性色与轻微纸页层次。

信息层级已确认：

- 悬浮信息是紧凑、即时可读的 `FIELD NOTE`。
- 放大查看是完整、可沉浸阅读的 `PILGRIM'S RECORD`。
- 所有游戏内可见文案使用英文。

## 2. 视觉规范

### 基础色与材质

| 用途 | 视觉规则 |
|---|---|
| 面板底色 | 墨蓝近黑，接近 `#0A111D` / `#101B28`，保持哑光。 |
| 正文 | 骨白与暖灰，接近 `#EEE5CF` / `#C7BFAC`。 |
| 分隔与框线 | 旧金与暗铜，接近 `#B99248` / `#6E4B25`；仅使用细线。 |
| 伤害 | 褪色砖红，不使用鲜红。 |
| 防御 | 冷钢蓝，不使用鲜黄。 |
| 治疗 | 暗青绿，不使用高饱和荧光绿。 |

界面使用 `StyleBoxFlat` 和现有字体资源建立双层纸页边、轻微内高光和冷黑阴影。禁止玻璃拟态、霓虹发光、大面积圆角和厚重金属花边。

### 悬浮：Field Note

悬浮面板沿用现有屏幕空间定位规则：优先显示在卡牌右侧，空间不足时切至左侧，纵向钳制在安全边距内，离开卡牌立即隐藏。

内容自上而下为：

1. 小号全大写的 `RARITY · TYPE`。
2. 卡牌名称。
3. 低饱和属性印记，内容使用 `8 STRIKE`、`2 GUARD`、`1 MEND` 这类英文短语。
4. 旧金分隔线。
5. 最多两行的效果说明；超出时截断，完整描述留给放大查看。
6. 可换行的英文标签行。

面板保持紧凑，不放置卡牌编号或重复的大型装饰。它不接收鼠标输入，不延长悬浮状态，也不遮挡拖拽流程。

### 放大：Pilgrim's Record

放大查看继续由完整屏幕遮罩承托，但内容改为横向档案面板：

- 左栏：放大的真实 `CardView` 实例；牌框、纸张厚度、未来插画和已有数值标签都直接沿用卡牌本体视觉。
- 右栏：`RARITY · TYPE`、名称、共享属性印记、完整描述和英文标签。
- 底部：低对比度关闭提示 `CLICK OUTSIDE OR PRESS ESC TO CLOSE`。

面板背景为墨蓝内页，四周仅保留旧金细线与克制的暗影。默认宽屏为左右双栏；受限尺寸下优先压缩边距和文字区，保证详情可阅读。

## 3. 场景与职责

```text
CardEntity
├─ CardView
├─ CardInfoOverlay (CanvasLayer, lazy child)
│  └─ CardInfo / Field Note
└─ CardZoomOverlay (CanvasLayer, runtime child)
   └─ ZoomBg
      └─ ZoomView / Pilgrim's Record
         ├─ CardPreview (CardView instance)
         └─ DetailColumn
            └─ CardDetailStatSeal × N
```

- `CardEntity` 继续拥有悬浮、点击、拖拽和放大生命周期；不负责拼接样式细节。
- `CardInfoOverlay` 继续只处理独立屏幕层、显示/隐藏和定位。
- `CardInfo` 负责 Field Note 的字段渲染与说明截断。
- `ZoomView` 负责完整档案信息与放大卡面预览。
- 新增 `CardDetailStatSeal` 可复用场景，负责单项属性的文字、颜色和边框。悬浮和放大视图都使用它，杜绝两套独立的属性样式。

所有界面层级引用 `RenderPriority`；不引入裸写的 `z_index` 或 `CanvasLayer.layer` 常量。

## 4. 数据与交互流

1. `CardEntity` 在鼠标进入时调用 `CardInfoOverlay.show_for_card(self)`。
2. Overlay 从 `CardEntity.card_instance.card_data` 刷新 Field Note，并在下一帧依据卡面屏幕矩形定位。
3. Field Note 依据属性值仅创建有效的 `CardDetailStatSeal`；无属性的印记不显示。
4. 左键的既有放大流程创建 `CardZoomOverlay`，并将相同的 `CardInstance` 传入 `ZoomView`。
5. `ZoomView` 使用同一份 `CardInstance` 生成详情字段和卡面预览，确保名称、稀有度、属性、描述与标签一致。
6. 点击遮罩外部或按下 `Esc` 后，`CardEntity` 关闭放大层并回到普通状态。

无效卡牌实例、缺失 `card_data` 或未知标签时，界面安全地不显示相应字段或使用英文兜底文案；不得因展示层异常影响卡牌交互。

## 5. 实施边界

本次包括：

- 重做 `card_info.tscn`、`zoom_view.tscn` 与相应脚本的字段布局和主题样式。
- 新增共享数值印记场景与属性到视觉样式的映射。
- 将卡牌详情标签全部切换为英文。
- 在 Zoom View 中放入真实卡牌预览。
- 使用现有 `RenderPriority` 管理层级。
- 新增或更新自动化测试，覆盖主题节点、英文内容、共享印记、卡面预览、悬浮定位与放大关闭路径。

本次不包括：

- 新的插画、牌框贴图、音效、粒子或动画资源。
- 固定侧栏、鼠标跟随提示、多卡牌对比、移动端触控布局。
- 修改卡牌数值、卡牌战斗逻辑、拖拽规则或主菜单流程。

## 6. 验收标准

1. 悬浮面板和放大查看均使用一致的墨蓝、旧金、骨白及低饱和属性色，且不再出现早期亮红、亮黄、亮绿的整块数值底色。
2. 悬浮面板在任意旋转卡牌旁保持屏幕正向，沿用右侧优先、左侧翻边与离开即隐藏规则。
3. 悬浮面板包含英文稀有度/类型、名称、有效属性、截断说明及英文标签；它不接受鼠标事件。
4. 放大查看展示真实放大卡面和完整英文详情，点击遮罩或按 `Esc` 都能关闭。
5. 共享 `CardDetailStatSeal` 在悬浮与放大界面中使用相同属性颜色和文案规则。
6. 所有新增层级值来自 `RenderPriority`，现有拖拽、点击、展示模式与放大流程不回归。
7. 相关 Godot 场景可加载，现有悬浮与放大测试以及新增针对 UI 结构的测试通过。
