# 事件棋盘 Hover 信息预览设计

**日期：** 2026-08-10
**状态：** 待实现
**范围：** 棋盘上的怪物、Boss、商店与宝藏事件的信息预览。

## 目标

玩家在放置卡牌前可悬停棋盘事件圈，获得足以支持路线与战斗决策的只读信息。重点是让玩家在触发战斗前得知残响的生命、掉落与能力。

本功能不得改变下列既有规则：

- 事件仍只能由卡牌放置并接触事件占用格触发。
- 悬停、预览和鼠标点击均不得打开事件弹窗、开始战斗或结算奖励。
- 已解决事件不再显示信息预览。

## 方案

采用“统一预览层 + 事件悬停信号”的结构。

### 组件职责

| 组件 | 职责 |
| --- | --- |
| `BoardEvent` | 保留事件圈显示；检测鼠标进入与离开；向外发送当前 `EventInstance` 与事件圈屏幕区域。不得格式化奖励或修改事件状态。 |
| `EventHoverPreviewCoordinator` | 订阅棋盘事件的悬停信号；选择显示位置；在鼠标离开时隐藏；仅协调，不解析各事件的业务数据。 |
| `EventHoverPreview` | 可复用的只读 `Control` 视图。接收预览模型并显示标题、类型、属性区、奖励区、能力区。使用 `MOUSE_FILTER_IGNORE`，不截获棋盘输入。 |
| `EventHoverPreviewFormatter` | 将 `EventInstance`、模板内容与运行时状态转换为稳定的预览模型。处理怪物、Boss、商店与宝藏的差异，避免 UI 直接依赖各 `EventContent` 子类。 |
| `EventHoverPreviewModel` | 视图专用的轻量数据对象：标题、类型标记、色调、属性行、奖励行、能力文本、是否可显示。 |

### 为什么不把面板放进每个事件圈

棋盘可以同时存在多个事件。统一预览层只实例化一个面板，并把奖励 / 状态格式化集中在一个位置；这能避免 `BoardEvent` 同时承担鼠标、布局、业务数据解析和 UI 文案职责。

## 交互与布局

1. 鼠标进入未解决事件圈时，`BoardEvent` 发送悬停开始信号。
2. 协调器通过格式化器构造预览模型；若模型可显示，则展示唯一的预览浮层。
3. 浮层优先位于事件圈右侧，留出固定间距。
4. 若右侧空间不足，则改为左侧；垂直位置钳制在视口内。
5. 鼠标离开事件圈时立即隐藏。预览本身忽略鼠标，因此不会拦截卡牌拖放或引入“事件点击入口”。
6. 已解决事件、缺少有效内容的事件均不显示预览。

## 各类型显示内容

### 普通残响（MONSTER）

- 残响名称与 `残响` 类型标记。
- **生命：** 优先读取本场遭遇的运行时生命；没有运行时遭遇状态时显示残响配置中的初始生命。
- **掉落：** 读取 `EncounterDropEntry`。金币显示数量或范围；卡牌显示名称；概率掉落明确标记百分比；必定掉落明确标记“必得”。
- **能力：** 显示怪物动作、战败效果或其它已配置能力的描述。未配置时显示“无额外效果”。

### Boss 残响（BOSS）

复用怪物预览布局，但使用 Boss 色调与 `BOSS` 标记。生命、掉落、能力均按运行时优先原则显示。地图机制造成的可见初始护甲也应列入属性区。

### 商店（SHOP）

- 商店名与 `商店` 类型标记。
- 仅列出尚未售罄的商品：卡牌名、点数、护甲、价格。
- 没有可用商品时显示“商品已售罄”。

### 宝藏（TREASURE）

- 宝藏名与 `宝藏` 类型标记。
- 若运行时奖励选项已经生成，显示可选数量与选项摘要。
- 若奖励尚未生成且会随机决定，仅显示奖励类别和选择数量，不提前泄露随机结果。

## 数据与状态原则

- 预览只读取 `EventInstance`、`EventContent` 及其 `EventRuntimeState`；不得调用 resolver、奖励发放或事件交互控制器。
- 运行时字段优先于模板字段，确保受伤残响、售罄商店等预览准确。
- 文案格式化由 `EventHoverPreviewFormatter` 集中管理；卡牌与掉落的数据对象只提供原始数据。
- 预览模型使用普通值类型 / `RefCounted`，不保留棋盘节点引用，避免事件移除后出现悬挂 UI 状态。

## 测试与验收

自动化测试至少覆盖：

1. 普通残响预览显示名称、生命、金币掉落、卡牌掉落和能力回退文案。
2. Boss 预览使用 Boss 标记，并显示生命与护甲。
3. 商店仅显示未售罄商品及价格。
4. 宝藏在奖励未生成时不泄露随机结果，在奖励已生成后显示摘要。
5. `BoardEvent` 对未解决事件发出 hover 信号，对已解决事件不发出可显示预览。
6. 预览浮层在右侧优先、空间不足时左移，并保持在视口边界内。
7. hover 不会调用任何事件触发、战斗或奖励结算路径。

人工验收：

- 在肋骨林地地图中，悬停啮髓鼠群、腐肋巨狼与白角守墓鹿，可在开始战斗前看见生命、掉落和能力。
- 悬停商店与宝藏可得到相应摘要。
- 鼠标移开后浮层消失；拖动卡牌经过事件时的接触触发行为保持不变。
