# 棋盘事件图标优先布局设计

**日期：** 2026-07-29
**目标：** 优化 `scenes/game/event.tscn` 的单格事件卡片，使图标成为主要识别信息，消除类型文本与怪物名称横向拥挤、名称折行的问题。

## 已确认的视觉方向

采用“图标主视觉 + 小型类别徽标 + 底部名称条”。事件卡片保持 `Control` 根节点和现有点击区域、信号、完成遮罩及棋盘本地定位行为不变。

## 布局规范（基准单格：80 × 80）

- **图标区**：卡片中央的主要区域。配置了 `EventData.icon` 时显示图标，并保持等比例居中。
- **类型徽标**：位于左上角，使用事件原有颜色与简短类型标记（如 `ENEMY`）。字号较小，只辅助区分类别，不与名称争夺空间。
- **名称条**：固定在底部，使用半透明深色背景。名称使用单行、居中和省略号截断，避免 `Forest Wolf` 这类名称折成两行。
- **无图标回退**：隐藏图标时，将类型标记放大并居中显示；名称仍保留在底部名称条，保证所有事件都有清晰的可读状态。
- **完成状态**：`ResolvedOverlay` 继续覆盖整个卡片，语义与选择禁用逻辑不变。

## 交互与数据边界

- 不修改 `BoardEvent.setup()` 的坐标和尺寸计算。
- 不修改 `event_selected(instance)` 信号和已完成/未绑定事件的防护逻辑。
- 不新增战斗、商店、掉落或棋盘放置依赖。
- 仅调整 `event.tscn` 的子节点尺寸、锚点、文字显示设置，以及必要的显示状态测试。

## 验收标准

1. 在 80 × 80 的预览事件中，图标是最醒目的视觉元素。
2. 有图标时，类型标签只占左上角小区域；怪物名称始终位于底部单行条内。
3. 无图标时，类型标记居中、尺寸明显，并且名称不折行。
4. 现有事件绑定、点击、已完成遮罩和棋盘定位测试继续通过。
5. 新增场景级断言，覆盖名称单行省略、图标优先和无图标回退布局配置。
