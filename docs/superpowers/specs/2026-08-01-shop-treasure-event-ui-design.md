# 商店与宝藏事件 UI 设计

**日期：** 2026-08-01
**状态：** 已确认，待实施计划
**范围：** 棋盘事件触发、商店事件、宝藏事件及其首版结算逻辑。

## 1. 目标与非目标

### 目标

- 卡牌推进牌链并进入事件圈时，自动开启对应的全屏事件面板。
- 商店事件能使用玩家的永久金币购买卡牌并加入当前手牌。
- 宝藏事件固定提供两个普通卡牌奖励与一个金币卡奖励，玩家三选一后结算事件。
- 所有事件奖励、售罄和结算状态均属于单次 `EventInstance`，不污染配置资源。
- 为后续怪物、Boss、剧情及陷阱事件复用相同的事件触发入口。

### 非目标

- 不制作永久牌库、卡牌收藏、商店刷新、退出确认或多怪物战斗。
- 不在本次实现中完成怪物事件的战斗 UI；怪物事件仅复用触发入口。
- 不实现事件圈重叠时的多事件选择器；地图生成规则保证首版不会出现该情况。

## 2. 术语

| 名称 | 定义 |
| --- | --- |
| 事件圈 | 棋盘中用于表示事件触发区域的 `EventInstance` 可视区域。 |
| 落牌 | 玩家将一张手牌合法放置到现有牌链末端，且位置已最终确认。 |
| 普通卡奖励 | 被选取后创建 `CardInstance` 与 `CardEntity`，并加入当前 `HandArea` 的卡牌奖励。 |
| 金币卡 | 宝藏面板上的金币奖励选项。它不是手牌卡牌，选择后仅增加永久金币。 |

## 3. 事件触发

### 3.1 触发时机

事件只在一张卡牌**成功落位**后检查：

1. 玩家将卡牌拖至合法位置；
2. 牌桌确认卡牌加入牌链并完成最终落位；
3. 棋盘仅以这张新落位卡牌的占格/碰撞范围检测未解决事件圈；
4. 命中唯一事件后锁定棋盘交互，并由 `GameManager` 打开相应事件面板。

拖拽预览、移动既有卡牌、失败落位均不得触发事件。`EventInstance.is_resolved == true` 的事件永不再次触发。

### 3.2 事件空间生成规则

事件在生成位置时必须遵循以下规则：

- 比较事件的完整实际占格范围（含 `EventData.size`），而非只比较原点；
- 任意两个事件区域的边缘之间至少存在一个棋盘单位的空白间隔；
- 该间隔保证合法的 2×1 卡牌不会同时与两个事件圈重叠；
- 随机位置不符合条件时重新抽取；超过限定尝试次数则跳过位置或降低本轮生成数量，并记录警告，以避免死循环；
- 触发层仍保留防御性检查：若异常地图数据使一张卡命中多个事件，记录错误且不连续打开多个事件面板。

首版不再以 `BoardEvent.event_selected` 作为商店与宝藏的主要入口。棋盘应提供统一信号：

```gdscript
signal event_triggered(event_instance: EventInstance)
```

`GameManager` 监听该信号，并按 `EventData.EventType` 分派到商店、宝藏或未来的战斗流程。

## 4. UI 与交互

### 4.1 通用事件遮罩

`EventOverlay` 是覆盖在棋盘上的全屏 UI 容器：

- 背景棋盘仍可见，但被深色遮罩覆盖；
- 遮罩阻止手牌、棋盘和拖拽操作；
- 中央展示与事件类型匹配的内容面板；
- 事件面板关闭后解除交互锁定；
- 已解决事件不会重新打开面板。

结构：

```text
GameManager
└─ EventOverlay
   ├─ EventShopPanel
   └─ EventTreasurePanel
```

### 4.2 商店面板

展示内容：

- 标题与当前 `PlayerData.gold`；
- 三个商品槽位；每个显示卡牌、价格、购买按钮和售罄状态；
- 购买结果反馈区。

购买流程：

1. 玩家点击未售罄商品；
2. `EventShopPanel` 向 `GameManager` 请求购买；
3. `GameManager` 依序检查商品状态、金币与手牌容量；
4. 校验成功时扣除金币，创建普通卡奖励对应的 `CardInstance` / `CardEntity` 并加入 `HandArea`，商品标记为售罄；
5. 面板刷新金币和商品状态。

失败反馈：

| 条件 | 结果 |
| --- | --- |
| 金币不足 | 不扣金币、不发卡、不售罄，提示“金币不足”。 |
| 手牌已满 | 不扣金币、不发卡、不售罄，提示“手牌已满”。 |
| 商品已售罄 | 拒绝重复购买并保持售罄显示。 |

首版不做商店刷新。商店在用户完成至少一次购买后仍可保持打开，以便购买其他商品；具体离开方式维持当前事件系统的关闭/返回能力，不在本功能中新增退出确认。

### 4.3 宝藏面板

每个宝藏事件在**第一次打开时**生成并缓存以下三个奖励选项：

```text
普通卡奖励 A + 普通卡奖励 B + 金币卡奖励
```

- 两张普通卡从 `EventTreasureContent.card_rewards` 中无放回抽取；不足两张则显示实际可得到的普通卡数量；
- 金币卡始终存在；金币数从 `gold_range` 仅随机一次并缓存；
- 选项重新打开同一未结算事件时保持完全一致，不能刷奖励；
- 所有选项显示卡牌/金币价值及可领取状态。

领取流程：

- 选普通卡：验证手牌容量；成功后创建并加入手牌；
- 选金币卡：直接增加 `PlayerData.gold`，不创建 `CardInstance`，也不检查手牌容量；
- 任一奖励成功领取后：锁定其他选项，调用 `EventInstance.resolve()`，自动关闭面板并解除棋盘交互锁定；
- 若选择普通卡时手牌已满：不领取、不结算、不关闭；玩家可在释放手牌容量后重试或改选金币卡。

## 5. 数据模型与状态归属

### 5.1 玩家持久数据

向 `PlayerData` 添加：

```gdscript
@export var gold: int = 30
```

`gold` 是跨事件保留的永久金币，由 `GameManager` 的结算入口修改。

### 5.2 静态配置

`EventTreasureContent` 保持为宝藏配置资源：

- `gold_range`：金币卡的随机范围；
- `card_rewards`：普通卡奖励池；
- `choices`：首版配置为 2，表示普通卡候选数。

商店的商品配置必须可序列化。若当前 `ShopItem extends RefCounted` 无法由 Inspector 配置，则拆分为：

- `ShopItemData extends Resource`：静态卡牌与价格配置；
- 商店事件运行时项目状态：商品的售罄标记。

禁止把一次事件的已售罄状态写回 `.tres` 配置。

### 5.3 单次事件运行时状态

`EventInstance` 持有本次事件的动态状态。宝藏可使用显式运行时奖励条目：

```text
TreasureRewardOption
├─ kind: CARD / GOLD
├─ card_data: CardData       # kind 为 CARD 时有效
└─ gold_amount: int          # kind 为 GOLD 时有效
```

它还需记录：

- 本次宝藏的已生成候选项；
- 是否已领取以及所选项；
- 本次商店商品的售罄状态；
- 已有的 `is_revealed`、`is_resolved`。

`EventInstance.resolve()` 是唯一的最终事件完成标记。无论金币或普通卡宝藏奖励成功领取，均只能调用一次。

## 6. 职责边界与数据流

```text
卡牌合法落位
  → Board 检测并发出 event_triggered(instance)
  → GameManager 按 EventType 分派
  → EventOverlay 打开 Shop / Treasure 面板
  → 面板发送“购买/领取”请求
  → GameManager 验证并结算
      ├─ 更新 PlayerData.gold
      ├─ 创建 CardInstance / CardEntity（普通卡时）
      ├─ 加入 HandArea
      ├─ 更新 EventInstance 运行时状态
      └─ 成功结束时调用 EventInstance.resolve()
  → EventOverlay 关闭并解除棋盘操作锁定
```

职责限制：

- `Board`：落牌后的事件检测与统一触发信号；不修改玩家金币，不发放奖励；
- `EventOverlay`：遮罩与面板开关；
- `EventShopPanel` / `EventTreasurePanel`：展示、按钮可用状态、反馈文本与结算请求；不得直接写入 `PlayerData` 或 `HandArea`；
- `GameManager`：唯一的购买/领取结算入口；
- `EventInstance`：只持有本次事件状态；
- `PlayerData`：只持有永久玩家数据。

## 7. 验收与测试

实现采用逻辑优先测试，至少覆盖：

1. 卡牌成功落位且重叠未解决事件时，只触发对应的唯一事件；
2. 拖拽预览、失败落位、已解决事件均不触发；
3. 事件生成遵守最少一个棋盘单位间隔，2×1 卡牌不能同时碰到两个事件；
4. 商店购买成功：金币正确扣除、卡牌加入手牌、商品售罄；
5. 商店金币不足：金币、手牌、商品状态均不变；
6. 商店手牌已满：金币不变、商品不售罄；
7. 宝藏初次生成固定为两张普通卡与一张金币卡；
8. 同一未完成宝藏重新打开，普通卡候选与金币数保持不变；
9. 领取普通卡后：卡牌入手、事件完成、其他选项不可再领；
10. 领取金币卡后：金币增加、手牌不增加、事件完成；
11. 宝藏普通卡领取时手牌已满：事件仍未完成，金币卡仍可领取；
12. 已解决事件不能重复打开、重复购买或重复领取。
