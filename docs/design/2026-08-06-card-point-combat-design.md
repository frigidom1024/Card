# 卡牌点数持续消耗战斗设计

**日期：** 2026-08-06  
**状态：** 已实施（基础点数对抗）
**范围：** 牌链遭遇战斗逻辑、卡牌点数损耗、牌根特殊处理、残响结果效果

## 1. 设计目标

将现有逐张卡牌触发伤害、防御、治疗以及怪物行动的战斗，简化为直观的点数比较：

> 从牌链末尾开始，卡牌当前点数与残响当前生命比较；卡牌点数归零才离场，残响生命归零即被击败。

棋盘、牌链连接、事件接触、牌桌持续存在和探索流程保持不变，主要修改战斗结算逻辑。

核心循环：

```text
购买更高点数卡牌 -> 组成牌链 -> 消耗残响生命 -> 保留有点数的卡牌 -> 获得金币升级 -> 挑战 Boss
```

## 2. 数据模型

### 卡牌

每张卡牌拥有：

- `max_points`：最大点数；
- `current_points`：当前点数；
- `armor`：初始护甲；
- `current_armor`：当前护甲。

`current_points` 和 `current_armor` 都是探索中的运行时状态。卡牌参与战斗后，损耗会保留到后续探索与遭遇。

### 牌根

牌根也拥有最大点数和当前点数，但点数归零时执行特殊处理：

```text
牌根 current_points = 0
-> 重置为 max_points
-> 从牌桌返回手牌区
```

牌根不会永久损失。

### 残响

残响保留：

- 最大生命 `max_hp`；
- 当前生命 `current_hp`；
- 奖励掉落；
- 结果惩罚；
- 可选的特殊战败效果。

## 3. 末尾优先结算

牌链：

```text
牌根 -> 卡牌 A -> 卡牌 B -> 卡牌 C
```

结算顺序：

```text
卡牌 C -> 卡牌 B -> 卡牌 A -> 牌根
```

每张仍有点数的卡牌只会与当前残响进行一次**同步点数对抗**：

1. 读取对抗前的残响生命作为本次反击值；
2. 卡牌以 `current_points` 对残响造成伤害；
3. 残响以步骤 1 记录的反击值攻击该卡牌；卡牌先消耗 `current_armor`，剩余伤害才消耗 `current_points`；
4. 残响生命归零，立即停止结算；否则继续向牌根结算。

因此，残响虽然会被卡牌削减生命，但其本次反击依然使用对抗开始前的生命值。护甲只保护卡牌，不参与残响的基础生命比较。

### 卡牌点数小于残响生命

```text
卡牌点数 2、护甲 1；残响生命 4

残响：4 -> 2
卡牌先承受 4 点反击：护甲 1 -> 0，点数 2 -> 0
卡牌耗尽，继续结算前一张卡牌
```

### 卡牌点数等于残响生命

```text
卡牌点数 4；残响生命 4

残响：4 -> 0（击败）
卡牌承受 4 点反击后耗尽
战斗结束
```

### 卡牌点数大于残响生命

```text
卡牌点数 7；残响生命 4

残响：4 -> 0（击败）
卡牌承受 4 点反击后保留 3 点
战斗结束
```

溢出点数不转化为其它资源。

## 4. 牌桌状态

- 普通卡牌只有 `current_points <= 0` 时才从牌桌移除；
- 未参与结算的卡牌不返回手牌、不扣点数，继续留在牌桌；
- 仍有点数的已使用卡牌继续留在牌桌；
- 牌根只有在实际结算后归零，才重置点数并返回手牌；
- 战斗中途击杀残响时，前方尚未结算的卡牌保持原状态。

示例：

```text
牌根 2 -> A 4 -> B 7 -> C 3
残响 4 生命

C：3，残响 4 -> 1，C 归零并移除
B：7，击杀残响，B 保留 6

战斗后：牌根 2、A 4、B 6 留在牌桌，C 被移除
```

## 5. 战斗结果

继续使用现有枚举：

```gdscript
enum Outcome { VICTORY, RETREAT, DEFEAT }
```

### `VICTORY`

残响生命归零，完成事件并发放已有金币和卡牌掉落。牌桌只反映本次实际点数损耗。

### `RETREAT`

当前牌链已经从末尾结算到牌根，但残响仍存活。残响保留已损失生命；未使用或未耗尽的卡牌留在牌桌；耗尽卡牌按牌桌规则结算。

遭遇协调器会在 `RETREAT` 结算后调用残响的 `gain_enhancement()`：残响生命上限和当前生命各增加其配置的 `enhancement_hp_bonus`（当前有 2 层上限）。这保留上一轮造成的伤害，同时让下一次挑战略微提高压力。

`RETREAT` 不再表示怪物行动，只表示当前牌链未能完成击杀。普通残响的 `actions` 不参与基础点数战斗。

### `DEFEAT`

保留给玩家失败流程。基础点数比较不主动插入普通怪物行动；特殊残响可以配置额外战败效果。

## 6. 惩罚和特殊残响效果

卡牌因点数归零而移除，与惩罚主动移除卡牌是两种不同机制：

```text
点数归零：基础战斗规则
惩罚移除：结果处理阶段的附加规则
```

现有 `CombatResult.penalties` 保留，可以继续承载：

- 移除牌链末尾卡牌；
- 残响强化；
- 扣除信仰值；
- 移动残响事件；
- 生成新的残响。

特殊残响建议按结果配置效果入口：

```text
on_retreat_effects
on_defeat_effects
on_victory_effects
```

例如：

- `RETREAT`：下次挑战自身恢复 2 点生命；
- `RETREAT`：获得 1 层强化；
- `DEFEAT`：玩家战败时扣除信仰值；
- `DEFEAT`：玩家战败时生成新的残响；
- `VICTORY`：Boss 击败后推进地图或回收神性。

`CombatService` 只负责点数比较和结果，不直接处理金币、信仰值、地图事件或牌桌节点。

## 7. 卡牌配合边界

卡牌配合不在战斗时临时计算 `synergy_bonus`。而是在一张卡牌被成功加入牌链时，由 `CardChainRuleService` 遍历牌链中全部卡牌的 `CardRule`，对新加入的卡牌执行规则。

规则生效后直接改变目标 `CardInstance` 的运行时状态：

- `current_points`：例如“下一张卡牌点数 +1”；
- `current_armor`：例如“下一张卡牌获得 1 点护甲”。

所以加成会持续保留到这张卡牌在后续战斗中被消耗、被移除或牌根重置；基础战斗服务不再理解“连锁加成”概念，只读取卡牌当前点数和当前护甲。

### 7.1 触发次数

每个 `CardRule` 使用自身的有效次数配置：

- `-1`：无限次；
- `0`：不触发；
- 正整数：该卡牌实例最多成功触发对应次数，例如 `2` 表示前两次有效。

触发计数保存在来源卡牌的 `CardInstance`，而不是共享的 `CardData` 上。因此同名卡牌的不同副本各自记录使用次数；规则只有在实际成功修改新卡牌时才消耗一次次数。

### 7.2 当前第一版的规则边界

CardRule 可以根据新增卡牌、来源卡牌及整条牌链的位置关系判断是否触发，例如：

- 来源卡牌朝向的相邻格（下一张）获得点数；
- 特定位置的卡牌获得护甲；
- 牌链头部卡牌获得即时点数或护甲；
- 连续放置满足条件时，给新卡牌加成。

CardRule 不应直接改动牌桌结构、回收或销毁其它卡牌、发放金币、扣除信仰值、移动事件或直接处理残响结果。那些副作用仍属于放置、遭遇或探索协调器。

## 8. 第一关平衡方向

| 内容 | 建议数值 |
|---|---:|
| 牌根最大点数 | 2 |
| 基础卡牌最大点数 | 1～3 |
| 配合卡最大点数 | 3～5 |
| 啮髓鼠群生命 | 3～4 |
| 腐肋巨狼生命 | 8～10 |
| 白角守墓鹿生命 | 18～22 |

目标：

- 啮髓鼠群通常消耗 1～2 张低点数卡牌；
- 腐肋巨狼需要 3～4 张有效卡牌或一张高点数卡牌配合；
- Boss 要求玩家完成商店购买和牌链构筑，而不是依赖初始牌组；
- 高点数卡牌击杀低生命残响后仍可保留部分点数。

## 9. 架构改动边界

主要修改：

- `CombatService2`：改为末尾向牌根的点数结算；
- `CombatContext`：增加反向牌链游标和卡牌点数变化记录；
- `CombatResult`：保留结果、残响状态、已处理卡牌和惩罚字段，废弃普通怪物行动结果字段；
- `CardData` / `CardInstance`：补充最大点数和当前运行时点数；
- 牌桌/卡牌管理器：处理普通卡牌归零移除、牌根归零重置回手；
- 残响配置：增加按 `RETREAT`、`DEFEAT`、`VICTORY` 配置效果的入口。

不修改：

- 棋盘尺寸和卡牌连接规则；
- 事件接触触发方式；
- 商店、宝藏、奖励掉落总体流程；
- Boss 追击服务的事件移动逻辑；
- 现有惩罚框架的结果传递方式。
